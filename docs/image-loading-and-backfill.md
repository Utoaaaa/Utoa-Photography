# 圖片載入與 960 / 1920 補齊

## 已實作

- 新增 `small`（長邊 960）與 `desktop`（長邊 1920）；等比例、不裁切、不放大原圖。WebP 品質沿用 85。
- 保留原圖及 `thumb` / `medium` / `large`。舊版實作以寬度 300 / 1200 / 3840 產生，與新版本的長邊定義不同。
- 前台依容器實際呈現寬度、照片比例及瀏覽器像素密度選圖；直幅 `srcset` 使用計算後的寬度。原圖尺寸不足時，不挑選放大過的舊版本。
- 首先顯示既有小預覽，高清圖解碼完成才淡入；減少動態偏好下直接切換。遠離可視範圍的高清圖不預先掛載。
- 相簿當前照片載入後，才以低優先級預載相鄰小預覽；節省流量／2G 連線不做此預載。
- 修正相簿桌機判定的 SSR hydration 不一致；封面資料補帶原始寬高。

## 後台使用

在 `/admin/uploads` 的「補齊 960 / 1920 圖片尺寸」區塊選擇：

- **補齊全部素材**：分頁讀取整庫素材清單，逐張補齊。
- **補齊所選**：只處理已勾選的照片。
- **暫停／繼續上次進度**：目前照片處理完後暫停；同一瀏覽器 localStorage 保存剩餘清單。
- **重試失敗項目**：保留成功結果，只重試失敗照片。後端仍逐一檢查尺寸，跳過已存在的物件。

此版本由開啟的後台頁面驅動短請求，不是關閉瀏覽器仍會執行的伺服器工作佇列。重新開啟後要按續跑；清除瀏覽器資料後可重新掃描，已存在版本不會重產。補齊不會刪除 1200 或原圖，也不會在載入頁面時自動開始。

新上傳照片（網站及 admin CLI）都會產生新增尺寸。CLI 原有跳過版本產生選項仍有效。

## 補齊前的相容行為

新增版本使用 `/images/:id/small`、`/images/:id/desktop` 穩定網址。R2 尚無對應物件時，分別讀取既有 medium / large；回退結果禁止快取，避免補齊後仍卡在舊版。精確命中新物件時才使用長效瀏覽器與邊緣快取。瀏覽請求不會觸發圖片產生或寫入 R2。

## 驗證範圍

單元／元件檢查涵蓋選圖寬度、解碼切換、舊請求隔離、離屏延後載入、失敗回退、部分生成失敗、補齊續跑／重試及過渡期快取。桌機與手機以本機測試資料驗證橫直幅、首頁封面、無水平溢出及無 hydration error。

尚未部署、未替正式照片執行補齊；本機示範素材不代表正式 CDN 的下載速度或攝影畫質。部署後應先勾選少量真實橫／直幅照片補齊，確認 960 / 1920 的實際尺寸、細節與檔案大小，再執行全庫。
