# 圖片載入與 960 / 1920 補齊

## 已實作

- 新增 `small`（長邊 960）與 `desktop`（長邊 1920）；等比例、不裁切、不放大原圖。WebP 品質沿用 85。
- 保留原圖及 `thumb` / `medium` / `large`。舊版實作以寬度 300 / 1200 / 3840 產生，與新版本的長邊定義不同。
- 前台依容器實際呈現寬度、照片比例及瀏覽器像素密度選圖；直幅 `srcset` 使用計算後的寬度。原圖尺寸不足時，不挑選放大過的舊版本。
- 首先顯示既有小預覽，高清圖解碼完成才淡入；減少動態偏好下直接切換。遠離可視範圍的高清圖不預先掛載。
- 相簿當前照片載入後，才以低優先級預載相鄰小預覽；節省流量／2G 連線不做此預載。
- 修正相簿桌機判定的 SSR hydration 不一致；封面資料補帶原始寬高。

## 後台使用

在 `/admin/uploads` 的「補齊 960 / 1920 圖片尺寸」區塊選擇：

- **補齊全部素材**：分頁讀取整庫素材清單，逐張補齊。
- **補齊所選**：只處理已勾選的照片。
- **暫停／繼續上次進度**：目前照片處理完後暫停；同一瀏覽器 localStorage 保存剩餘清單。
- **重試失敗項目**：保留成功結果，只重試失敗照片。後端仍逐一檢查尺寸，跳過已存在的物件。

此版本由開啟的後台頁面驅動短請求，不是關閉瀏覽器仍會執行的伺服器工作佇列。重新開啟後要按續跑；清除瀏覽器資料後可重新掃描，已存在版本不會重產。補齊不會刪除 1200 或原圖，也不會在載入頁面時自動開始。

新上傳照片（網站及 admin CLI）都會產生新增尺寸。CLI 原有跳過版本產生選項仍有效。

## 補齊前的相容行為

前台圖片直接使用圖片網域的靜態物件 URL，包含 small / desktop。若新版本尚未產生，瀏覽器移除新尺寸候選、改用既有 thumb / medium / large；再失敗時至多嘗試一次 large，並保留預覽，不反覆重試。瀏覽請求不會觸發圖片產生或寫入 R2。

正式版瀏覽器在缺少 build-time NEXT_PUBLIC 設定時，預設使用本專案 `https://images.utoa.studio`；Wrangler runtime vars 不會自動注入瀏覽器 bundle。既有 `/images/:id/small|desktop` 連結只用 R2 head 檢查存在性，再以 no-store 302 導向圖片網域，網站 Worker 不接收或複製圖片內容。沒有公開圖片網域的環境保留單一串流回應，但不做 clone + 等待 cache.put。

移除 next.config 的 `/images/:path*` 全域 immutable 標頭；它會蓋過回退及錯誤回應的 no-store。圖片快取由各路由／CDN 自己決定。

注意：圖片網域可快取 404。2026-09-16 的正式觀測中，缺失 desktop.webp 回應含 `Cache-Control: max-age=14400`。補齊後若 CDN 尚保留先前 404，前台會繼續使用舊高清版本直到該快取過期或經授權清除；不能保證補齊後立刻全站切到新尺寸。

## 驗證範圍

單元／元件檢查涵蓋選圖寬度、解碼切換、舊請求隔離、離屏延後載入、失敗回退、部分生成失敗、補齊續跑／重試及過渡期快取。桌機與手機以本機測試資料驗證橫直幅、首頁封面、無水平溢出及無 hydration error。

1102 後續修正尚未部署，未替正式照片執行補齊；本機示範素材不代表正式 CDN 的下載速度或攝影畫質。部署後應先勾選少量真實橫／直幅照片補齊，確認 960 / 1920 的實際尺寸、細節與檔案大小，再執行全庫。

## 部分直幅縮小與切換閃光修正

江之島相簿第六張 `r2-cli-648a627828ba31d3` 在頁面資料中登記 7008 × 4672，但既有 thumb / medium / large 分別為 300 × 450、1200 × 1800、3840 × 5760。橫幅容器套到實際直幅，導致照片縮小；與是否已生成新尺寸無關。

前台先用縮圖辨識明確的寬高顛倒，高清解碼後核對實際比例；不修改既有資料庫。窄於 1024px 的捲動相簿以可用寬度顯示，桌機保留視窗高度上限。CLI 新匯入時會將 EXIF 5–8 的寬高對調後登記，避免再次記入未旋轉尺寸。

預覽保持不透明，高清解碼完成後僅讓上層淡入；不再讓兩層同時變透明，也移除單張模式的整體降亮度切換。尚未 resizing 的照片仍使用既有尺寸回退。這些修正尚未部署。
