# 新版管理工作區

- `/admin/workspace`：真實管理 API，使用既有 Cloudflare Access 與管理員權限。
- `/admin/demo`：保留模擬資料，操作不發出管理 API 請求。
- `/admin`：原控制台保留，新增新版工作區入口。

兩個入口共用 `src/components/admin/AdminWorkspace.tsx` 的卡片、排序與預覽版面；API 格式轉換集中在 `src/components/admin/workspace/api.ts`。

## 已接回的流程

年份讀取、新增、名稱儲存、發布狀態、排序與刪除；地點讀取、新增、名稱／Slug／摘要／封面儲存、排序與刪除；作品集讀取、新增、編輯、拍攝日期、封面、發布狀態、地點指派／解除、排序與刪除；作品集照片的加入、移除、排序及真實影像預覽。

媒體區重用目前 `/admin/uploads` 的實際上傳、資料編輯、批次加入作品集、刪除、影像版本補建與孤兒檔清理 UI。離開媒體區後重新讀取工作區資料，不另建第二套上傳端點。

## 儲存規則

- 真實資料只有 `draft`、`published`，不送出 demo 的 `review`。
- 發布作品集前必須有地點；地點指派使用獨立 `/location` API。
- 有作品集的地點刪除交由既有 API 拒絕。年份使用一般刪除，不自動升級強制刪除。
- 儲存期間停用重複操作。成功後重新讀取；失敗顯示伺服器錯誤，保留表單輸入。
- 現有年份／作品集排序與複合編輯不是跨請求交易。中途失敗可能部分完成；工作區會重新讀取並提示核對，不宣稱回滾。
- API 拒絕登入或讀取失敗時不以 demo 資料替代。重新讀取也失敗時停用寫入，避免繼續操作過時資料。
- 年份新增委派既有共用 API，保留驗證、審計、快取更新及 D1／Prisma 支援。

## 驗收

自動化測試用隔離的 fetch／資料層替身，不寫入正式資料，涵蓋讀取、儲存後重讀、錯誤保留草稿、401、指派端點、照片解除關聯、排序部分失敗、demo 不發請求及媒體元件掛載。

本次本機 `/admin/workspace` 回應 401，已確認未登入時拒絕存取。真實 D1／R2 的寫入驗收尚待有管理權限的環境，不能以單元測試取代：

1. 建立測試草稿年份、地點及作品集，編輯名稱／日期／封面，重載確認。
2. 指派／解除地點、調整排序；測試有作品集地點的刪除衝突。
3. 上傳一張測試照片，加入作品集並預覽；返回工作區確認同步。
4. 用可刪除的測試資料驗證批次操作及錯誤回饋，再依序清理測試紀錄。

不需停用驗證或修改 Access 規則來執行驗收。未部署，原版後台仍保留。
